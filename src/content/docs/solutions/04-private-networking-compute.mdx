## Expected private endpoint DNS resolution

After correct deployment, DNS lookup from inside the spoke VNet should return private IPs:

| Service | FQDN | Expected IP range |
|---|---|---|
| Key Vault | `cfs-kv-swc.vault.azure.net` | `10.1.3.x` |
| Storage | `cfsstswc.blob.core.windows.net` | `10.1.3.x` |
| SQL | `cfs-sql-swc.database.windows.net` | `10.1.3.x` |

If DNS returns a public IP (e.g. `52.x.x.x`), the Private DNS Zone is not linked to the VNet.
Fix: add a VNet link on `privatelink.vaultcore.azure.net` for `cfs-app-vnet-swc`.

```bash
az network private-dns link vnet create \
  --resource-group rg-cfs-app-swc \
  --zone-name privatelink.vaultcore.azure.net \
  --name cfs-app-vnet-link \
  --virtual-network cfs-app-vnet-swc \
  --registration-enabled false
```

## Front Door → App Gateway Private Link (key configuration)

The most common pupil mistake is configuring Front Door to use the App Gateway's public IP
directly, bypassing the WAF. The correct configuration:

1. App Gateway has a **private frontend IP** only (or public + private)
2. Front Door origin type is **Application gateway** with Private Link enabled
3. The Front Door origin approval request must be approved on the App Gateway resource

```bash
# Check pending Private Link approvals on App Gateway
az network application-gateway private-link-resource list \
  --gateway-name cfs-app-agw-swc -g rg-cfs-app-swc -o table

# Approve Front Door's Private Link connection
az network private-endpoint-connection approve \
  --resource-name cfs-app-agw-swc \
  --resource-group rg-cfs-app-swc \
  --type Microsoft.Network/applicationGateways \
  --name <connection-name>
```

## Common pitfalls

| Pitfall | Root cause | Fix |
|---|---|---|
| DNS resolves to public IP | DNS zone not linked to spoke VNet | Add VNet link on each `privatelink.*` DNS zone |
| Front Door returns 502 | Private Link connection not approved on App Gateway | Approve the pending Private Endpoint connection |
| App Gateway in Detection mode | Wrong WAF mode in Bicep parameters | Update `wafMode: 'Prevention'` and redeploy |
| Public IP on compute VMs | NIC configuration error | Remove public IP from NIC; restart VM |
| Bastion connection fails | Bastion in wrong subnet or wrong SKU | Bastion must be in AzureBastionSubnet; Standard SKU for IP-based connection |
