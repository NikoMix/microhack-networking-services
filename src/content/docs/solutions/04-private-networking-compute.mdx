## Expected private endpoint DNS resolution

After correct deployment, DNS lookup from inside the spoke VNet should return private IPs:

| Service | FQDN | Expected IP range |
|---|---|---|
| Key Vault | `cfs-kv-swc.vault.azure.net` | `10.1.1.x` |
| Storage | `cfsstswc.blob.core.windows.net` | `10.1.1.x` |

If DNS returns a public IP (e.g. `52.x.x.x`), the Private DNS Zone is not linked to the VNet.
Fix: add a VNet link on `privatelink.vaultcore.azure.net` for `cfs-app-vnet-swc`.

```bash
az network private-dns link vnet create \
  --resource-group rg-cfs-spoke-swc \
  --zone-name privatelink.vaultcore.azure.net \
  --name cfs-app-vnet-link \
  --virtual-network cfs-app-vnet-swc \
  --registration-enabled false
```

## Front Door → App Gateway Private Link (key configuration)

The most common pupil mistake is configuring Front Door to use the App Gateway's public IP
directly, bypassing Private Link. The correct configuration (as implemented in
`infra/bicep/modules/app-gateway.bicep` + `front-door.bicep`):

1. App Gateway keeps its **public frontend** (required for the v2 control plane) and exposes a
   **Private Link configuration** on that frontend, with IP configs in the dedicated
   `snet-agw-pl` subnet (`10.1.4.0/24`, `privateLinkServiceNetworkPolicies: Disabled`).
2. Front Door Premium origin type is **Application gateway** with a `sharedPrivateLinkResource`
   whose `groupId` is the App Gateway frontend IP config name and `privateLink.id` is the App
   Gateway resource ID — so Front Door reaches the origin privately, not over the public IP.
3. The Front Door origin Private Link request lands **Pending** and must be approved on the App
   Gateway. `deploy.ps1`/`deploy.sh` and `deploy.yml` auto-approve it for `component=all`/`edge`;
   to do it manually:

```bash
APPGW_ID=$(az network application-gateway show \
  --name cfs-app-agw-swc -g rg-cfs-spoke-swc --query id -o tsv)

# Check pending Private Link connections on the App Gateway
az network private-endpoint-connection list --id "$APPGW_ID" -o table

# Approve Front Door's Private Link connection (generic --id form)
CONN_ID=$(az network private-endpoint-connection list --id "$APPGW_ID" \
  --query "[?properties.privateLinkServiceConnectionState.status=='Pending'].id" -o tsv)
az network private-endpoint-connection approve --id "$CONN_ID" \
  --description "Approved Front Door Premium origin"
```

## Common pitfalls

| Pitfall | Root cause | Fix |
|---|---|---|
| DNS resolves to public IP | DNS zone not linked to spoke VNet | Add VNet link on each `privatelink.*` DNS zone |
| Front Door returns 502 | Private Link connection not approved on App Gateway | Approve the pending Private Endpoint connection |
| App Gateway in Detection mode | Wrong WAF mode in Bicep parameters | Update `wafMode: 'Prevention'` and redeploy |
| Public IP on compute VMs | NIC configuration error | Remove public IP from NIC; restart VM |
| Bastion connection fails | Bastion in wrong subnet or wrong SKU | Bastion must be in AzureBastionSubnet; Standard SKU for IP-based connection |
