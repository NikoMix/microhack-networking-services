## What-if output — expected changes

A correct `what-if` output should show:
- `+` Create: VNet, subnets, Firewall, Bastion, Gateway, Public IPs, Route Tables, NSGs
- `~` Modify: none (first deployment)
- `-` Delete: none

**Red flags in what-if output** (challenger should catch these):
- Any resource in a subnet other than AzureFirewallSubnet, AzureBastionSubnet, GatewaySubnet
  having a public IP → investigate
- Route `0.0.0.0/0` on GatewaySubnet → must NOT override (this breaks BGP routing)
- Missing UDR on spoke subnets → egress bypass risk

## Quota bypass options

If Azure Firewall or VPN Gateway quota is unavailable:

| Resource | Quota issue | Fallback |
|---|---|---|
| Azure Firewall | `QuotaExceeded` in region | Deploy Basic SKU for lab (note Premium is production recommendation); or use NSGs + Azure Firewall Basic |
| VPN Gateway | No capacity | Reduce to Basic SKU (`az network vnet-gateway create --sku Basic`); show VWAN as a portal demo |
| Public IPs | Limit reached | Request quota increase, or share IPs between pupils |

## Common pitfalls

| Pitfall | Root cause | Fix |
|---|---|---|
| `deploy.yml` fails at OIDC login step | Secrets not set or wrong subscription | Recheck `AZURE_CLIENT_ID`, `AZURE_TENANT_ID`, `AZURE_SUBSCRIPTION_ID` in repo secrets |
| Peering shows Disconnected | One side created before the other | Delete both peerings and recreate in the same Bicep deployment |
| Firewall created as Standard instead of Premium | Wrong SKU in parameters | Update `firewallSku` parameter to `Premium`; redeploy |
| Route on GatewaySubnet pointing to Firewall | Misconfigured UDR | Remove the UDR from GatewaySubnet — this breaks BGP; spoke UDRs only |
| Gateway takes >60 min | Rare Azure provisioning delay | Wait; do not cancel; retrigger only if run shows failed |
