## Reference HLD summary (B.2.1)

### Topology

```
Hub VNet: cfs-hub-vnet-swc (10.0.0.0/16)
  Subnets:
    AzureFirewallSubnet         10.0.0.0/26

Spoke VNet: cfs-app-vnet-swc (10.1.0.0/16)
  Subnets:
    snet-workload               10.1.0.0/24  (private compute, no public IPs)
    snet-pe                     10.1.1.0/24  (Private Endpoints)
    snet-appgw                  10.1.2.0/24  (App Gateway dedicated)

VNet Peering: Hub ↔ Spoke (allow-gateway-transit: hub; use-remote-gateway: spoke)
UDR on snet-workload + snet-lb: 0.0.0.0/0 → cfs-hub-afw-swc private IP (10.0.0.4)
```

### ALZ design areas — reference answers

| Design area | CFS reference answer |
|---|---|
| **Networking topology** | Hub & spoke. Single hub in swedencentral, one spoke per workload tier. No VWAN in lab (documented as production recommendation). |
| **Connectivity** | VPN Gateway for branches, ExpressRoute design-only for DC. BGP enabled. On-prem DNS conditional forwarder to Azure DNS. |
| **Identity** | Entra ID P2. PIM for Network Contributor and Security Admin. Bastion Standard for admin access. No jump-box VMs. |
| **Security** | Azure Firewall Premium with IDPS (Alert+Deny). NSG on all subnets. Private Endpoints for all PaaS. WAF on App Gateway and Front Door (Prevention mode, CRS 3.2). |
| **Management** | Log Analytics workspace in hub subscription. Network Watcher enabled. NSG flow logs version 2 with Traffic Analytics. Microsoft Defender for Cloud (CSPM). |
| **Governance** | Management group: Landing Zone > Corp > CFS. Policy: Deny public endpoints, enforce TLS 1.2+, enforce resource tagging. Budget alert at €80. |

### Key design decisions (reference decision log)

| Decision | Chosen | Rationale |
|---|---|---|
| Firewall SKU | Premium | IDPS required for PSD2 Article 95 network isolation |
| Admin access | Bastion Standard | No public IPs on compute; Bastion enables file transfer (Standard feature) |
| Private DNS | Azure Private DNS Zones in hub | Centralised; auto-registration; no custom DNS server needed in lab |
| Front Door SKU | Premium | Required for Private Link to App Gateway origin |
| ExpressRoute | Design-only | €200+/month; branch VPN is sufficient for lab |

## Reference WAR scores (B.2.2)

### Security pillar

| Finding | Severity | Current | Target | Recommendation |
|---|---|---|---|---|
| Network segmentation | High | 3 | 5 | Implement Azure Firewall IDPS in Alert+Deny mode; add micro-segmentation NSG rules |
| Identity and access | Medium | 3 | 4 | Enable PIM for all privileged network roles; enforce MFA |
| Data protection | Medium | 4 | 5 | Enforce Private Endpoints for all PaaS; disable public network access via Azure Policy |
| Threat detection | Low | 2 | 4 | Enable Microsoft Defender for Cloud; integrate NSG flow logs with Sentinel |

**Security pillar score: Current 3/5 → Target 4.5/5**

### Reliability pillar

| Finding | Severity | Current | Target | Recommendation |
|---|---|---|---|---|
| Zone redundancy | High | 2 | 5 | Deploy Firewall, App Gateway, and Bastion as zone-redundant; use ZRS storage |

**Reliability pillar score: Current 2.5/5 → Target 4.25/5**

## Common pitfalls

| Pitfall | Impact |
|---|---|
| HLD replicates the requirements document instead of designing the solution | B.2.1 fail — HLD must show topology and service selection, not requirements |
| WAR uses generic Microsoft guidance instead of CFS-specific findings | B.2.2 partial — findings must reference CFS context (PSD2, branch count) |
| Only one WAF pillar covered | B.2.2 fail — minimum 2 pillars; Security is mandatory |
| WAR scoring without justification (just numbers) | B.2.2 partial — each score needs a 1-line rationale |
| Design decisions listed without alternatives | B.2.1 partial — auditor wants to see options considered |
| Missing topology diagram | B.2.1 fail — a diagram (even text-based) is required |

## Grading hints

### B.2.1 HLD

- **Excellent**: Mermaid or visio-quality diagram, all 6 ALZ areas, decision log with 5+ entries including rationale and trade-offs, CFS-specific throughout.
- **Pass**: Text topology, 5+ ALZ areas, 3+ decisions with rationale.
- **Fail**: No topology, or fewer than 4 ALZ areas, or decision list without rationale.

### B.2.2 WAR

- **Excellent**: Security + Reliability + 1 additional pillar, maturity scores with justification, CFS-specific findings, prioritised recommendations with Azure service references.
- **Pass**: Security + Reliability, maturity scores, 3+ findings per pillar, some CFS specificity.
- **Fail**: Only 1 pillar, or Security pillar missing, or all recommendations are generic Microsoft advice.
