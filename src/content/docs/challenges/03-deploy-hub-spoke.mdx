## Objectives

Deploy the four core hub networking resources for CFS to your Azure subscription:

1. **Hub VNet** (`cfs-hub-vnet-swc`) with spoke peering
2. **Azure Firewall Premium** (`cfs-hub-afw-swc`) — central egress and segmentation
3. **Azure Bastion Standard** (`cfs-hub-bas-swc`) — private admin access, no public IPs on compute
4. **VPN / Virtual WAN Gateway** (`cfs-hub-gw-swc`) — hybrid connectivity to branches

This challenge satisfies **B.3.1** (scenario implementation) and starts evidence for
**B.3.2** (≥5 native Azure networking services). Challenge 04 completes the B.3.2 service count.

## Module B controls

> The partner has implemented at least one of the five Module B network scenarios for the
> customer engagement and can demonstrate the deployment in the customer's Azure environment.

CFS covers **Scenario 1** (secure network infrastructure) and **Scenario 2** (on-prem/branch

### B.3.2 — ≥5 Native Azure Networking Services

> The partner's implementation uses five or more of the native Azure networking services

Services deployed in this challenge: Virtual Network + VNet Peering, Azure Firewall,
Azure Bastion, VPN Gateway (or Azure Virtual WAN). Challenge 04 adds Private Link,
Application Gateway + WAF, Azure Front Door + WAF, and Azure Load Balancer (total: 8+).

## Part 0 — Start the gateway NOW (already done if you followed the banner above)

<Steps>
1. Trigger the gateway deployment immediately:
   ```bash
   gh workflow run deploy.yml -f component=gateway -f location=swedencentral
   gh run watch
   ```
2. While the gateway builds, continue to Part A. You will validate the gateway in the
   "Validation" section at the end of this challenge.
</Steps>

## Part A — Review and parameterise the Bicep

<Steps>
1. Ask the `iac-engineer` agent to review the hub parameters:
   ```
   @iac-engineer Review infra/bicep/parameters/lab.bicepparam for the CFS hub deployment.
   Confirm naming follows cfs-<role>-<type>-swc, region is swedencentral, and env=lab tag is set.
   ```
2. Open `infra/bicep/parameters/lab.bicepparam` and confirm:
   - `location = 'swedencentral'`
   - `namePrefix = 'cfs'` and `regionToken = 'swc'` — resource names compose to `cfs-<role>-<type>-swc`
   - `environmentName = 'lab'`
   - `deployVpnGateway = true`
   - `adminSshPublicKey` is set to your OpenSSH public key (required to deploy the private VM in Challenge 04)
3. Run `what-if` validation:
   ```bash
   az deployment sub what-if \
     --location swedencentral \
     --template-file infra/bicep/main.bicep \
     --parameters infra/bicep/parameters/lab.bicepparam \
     --name "cfs-hub-whatif-$(date +%s)"
   ```
4. Review the `what-if` output with the agent:
   ```
   @iac-engineer Review this what-if output. Are there any resources that should not be
   created? Any naming deviations? Any public IP resources outside of expected ones?
   ```
5. Invoke the challenger on the plan:
   ```
   @challenger Review the what-if output for the CFS hub deployment. Flag any resources
   with public IPs that are not Azure Firewall, Bastion, or a VPN gateway public IP.
   ```
</Steps>

## Part B — Deploy the hub VNet, Firewall, and Bastion

<Steps>
1. Trigger the full hub deployment:
   ```bash
   gh workflow run deploy.yml -f component=hub -f location=swedencentral
   ```
   Or from the GitHub Actions UI: **Actions → deploy.yml → Run workflow**.

2. Monitor the deployment:
   ```bash
   gh run watch
   ```

3. Verify resources in Azure Portal or CLI after the run succeeds:
   ```bash
   az network vnet list -g rg-cfs-hub-swc -o table
   az network firewall list -g rg-cfs-hub-swc -o table
   az network bastion list -g rg-cfs-hub-swc -o table
   ```

4. Confirm routing: the hub route table should force all spoke traffic through the Firewall:
   ```bash
   az network route-table route list \
     --route-table-name cfs-hub-rt-swc -g rg-cfs-hub-swc -o table
   ```
   The default route `0.0.0.0/0` should point to the Firewall private IP.
</Steps>

## Part C — Deploy the spoke and configure VNet peering

<Steps>
1. Deploy the app spoke:
   ```bash
   gh workflow run deploy.yml -f component=spoke -f location=swedencentral
   ```

2. Verify VNet peering is bidirectional and connected:
   ```bash
   az network vnet peering list \
     --vnet-name cfs-hub-vnet-swc -g rg-cfs-hub-swc -o table
   az network vnet peering list \
     --vnet-name cfs-app-vnet-swc -g rg-cfs-app-swc -o table
   ```
   Both peerings should show state `Connected`.

3. Confirm the spoke route table forces egress through the hub Firewall (User-Defined Route):
   ```bash
   az network route-table route list \
     --route-table-name cfs-app-rt-swc -g rg-cfs-app-swc -o table
   ```
</Steps>

## Part D — Validate the gateway (when ready)

<Aside type="note" title="Gateway timing">
If the gateway deployment from Part 0 is still running, continue to the evidence section
and come back here once `gh run watch` shows the gateway run as **completed**.
</Aside>

<Steps>
1. Verify the VPN gateway is provisioned:
   ```bash
   az network vnet-gateway show \
     -n cfs-hub-gw-swc -g rg-cfs-hub-swc \
     --query '{name:name, provisioningState:provisioningState, sku:sku.name}' -o json
   ```
   Expected: `provisioningState: Succeeded`.

2. Note the gateway's public IP for the implementation plan artifact.
</Steps>

## Validation checklist

| Check | Command / Portal |
|---|---|
| Hub VNet and spoke VNet exist in Sweden Central | `az network vnet list -o table` |
| VNet peering is `Connected` both ways | `az network vnet peering list` |
| Azure Firewall is `Succeeded` | `az network firewall list -g rg-cfs-hub-swc` |
| UDR `0.0.0.0/0` → Firewall private IP on spoke route table | Portal: Route tables |
| Bastion is `Succeeded` | `az network bastion list` |
| VPN Gateway is `Succeeded` (may take up to 45 min) | `az network vnet-gateway show` |
| No VM has a public IP | `az network public-ip list -o table` — only expected PIPs listed |
